# Проверки переноса

Дата: 28 октября 2026. SDK Flutter 3.47.8 / Dart 3.13.7, Linux x64.

## Подтверждено

- Финансовые модели и расчёты: 13 unit-тестов, включая исключение корректировок, границы месяца, CSV, точное локальное хранение целых сотых и локальный месяц бюджета после серверного UTC round trip. Проверка часового пояса также запускалась с `TZ=Europe/Moscow`.
- Хранилище: 10 тестов — восстановление, dirty/tombstone, каскады, rollback курсора, scoped accounts, headless store, два экземпляра store, logout и ротация токенов между engines.
- HTTP-протокол: 7 MockClient-тестов — auth, пакетная отправка, страницы, ошибки и валидация.
- RuntimeLock: 3 Dart channel-теста. Web origin-wide Web Locks проверены компиляцией JavaScript и Node 24 native navigator.locks (владение, ожидание, освобождение, повторное получение и отказ без secure context/API). Android Java release compilation и 3 JVM-теста: сериализация потоков, повторное освобождение, прерывание ожидания, реальное межпроцессное состязание за file lock.
- Интерфейс: 22 widget/screenshot-теста. Все пять экранов с пустой и заполненной базой на 320×568, 390×844 и 1280×900, формы и ошибки ввода, CRUD операций/категорий/бюджетов, текст 1.5×, тёмная тема, отрицательная корректировка, CSV через save selector и share sheet с проверкой байтов.
- Настоящий Go HTTP-сервер: регистрация, вход, `/me`, 1102 записи, страницы `[500,500,102]`, изменения, удаление, replay старой записи, изоляция двух пользователей, refresh rotation и отзыв refresh после logout. Запуск: `bash tool/run_integration.sh` (нужны Go 1.25+ и Dart).
- Общий финальный запуск: **55 Flutter-тестов прошли**, `flutter analyze` — **No issues found**.
- Web JavaScript release с локальным CanvasKit и Linux x64 release собраны. Android universal release APK также собран и снабжён отдельной тестовой подписью; проверяются apksigner и 16 KiB zipalign. WorkManager Kotlin/AGP compatibility настроена в runner Gradle.
- Go-сервер не изменялся; cloud-capabilities удалены из Apple templates, SwiftData явно локальный.

В исходном checkout отсутствует `BalanceServer/cmd/balance-server`, хотя README и Dockerfile на него ссылаются (каталог исключается исходным ignore pattern). Поэтому integration runner создаёт временный `main` **только во временной копии**, вызывая исходные config/database/httpapi; исходный сервер остаётся без изменений. Это ограничение исходного репозитория, а не изменение протокола или сервера в переносе. Для обычной серверной Docker-сборки нужен оригинальный entry point; уже работающий Go-сервер можно использовать напрямую.

## Что ещё требует целевой среды

- iOS/iPadOS, macOS, Windows и watchOS не собирались в этой Linux-среде. Runners и CI созданы; реальные результаты CI не получены.
- watchOS — сохранённый нативный SwiftUI target, не Flutter. Material 3 относится к Flutter-клиенту.
- Полная проверка WorkManager после закрытия/остановки приложения, system Keychain/Keystore, iPad share popover, файловых диалогов, доступности и реальной клавиатуры требует устройств.
- Linux release слинкован, но запуск GTK под Xvfb/DBus был заблокирован ограничением сокетов среды. Локальные финансы и запуск store проверены unit/widget-тестами; реальный Secret Service пользователя здесь не проверен.
- Web runtime в настоящем браузере, CORS с пользовательским сервером, PWA install/offline reload и обновление кэша здесь не проверялись.
- Подпись Apple, публикация и магазины не выполнялись. Android тестовая подпись, если приложена, предназначена для проверки установки.
- Перенос старой SwiftData/Room базы выполняется через существующий сервер; прямого чтения чужого sandbox нет. Старое приложение следует сохранить до сверки данных.

## Принятые различия

Material 3 и адаптивная навигация; денежные значения в целых сотых (старые доли менее сотой округляются); границы периодов `[start,end)`; отдельные данные аккаунтов; график динамики — пары столбцов. CloudKit удалён по прямому запросу. Финансовые payload, UUID, даты обновления, корректировки, категории, бюджеты и удаления совместимы с исходным сервером.

## Обновление 4.1 — режимы и пресеты

Добавлены Лес, Индиго, Океан, Роза и OLED. Режим (system/light/dark) и пресет сохраняются независимо в локальных настройках. При выборе OLED сначала включается dark; затем разрешено выбрать system. В тёмном OLED все основные Material surfaces, карточки, app bar, навигация и диалоги используют `#000000`, overlay tint отключён.

Общий запуск после изменений: 62 Flutter-теста PASS; анализатор No issues found. Новые проверки: точные цвета OLED, разные акценты пресетов, сохранение/перезапуск, реакция системного режима на OS brightness, выбор на экране 320px и проверка чёрных пикселей снимков 390/1280px.

APK 4.1 использует новый тестовый ключ, поскольку временный ключ предыдущей тестовой сборки не сохранился после смены среды. Прямая установка поверх APK 4.0 с другой подписью невозможна. Перед заменой старой тестовой сборки синхронизируйте её с Go-сервером и убедитесь в сохранности данных. Для последующих сборок ключ 4.1 сохранён отдельно от репозитория и исходного архива. Для публикации нужен собственный release keystore.

Первая правка после обновления переносит старый снапшот в формат по записям, один раз: 0,09 с для 1 000, 0,35 с для 10 000 и 1,7 с для 50 000 операций. Из 10,8 с входа при 50 000 около 1,8 с занимает обработка синхронизации без диска (замер с `BALANCE_BENCH_MEMORY=1`). Остальное — разовая массовая запись гостевых данных и очереди из 50 000 изменений и её удаление после отправки.

Что изменено:
- `AppStore` перечитывает журнал и защищённое хранилище сессии только при смене `ledgerRevision` или `sessionRevision`, а не перед каждой операцией.
- `LedgerStorage` держит Sembast открытым и после каждой записи ждёт `flush`, чтобы запись была на диске до снятия блокировки.
- Журнал хранится по записям, пишутся только изменённые записи вместе с курсором, одной транзакцией.
- `_now()` больше не перебирает всю очередь, отсортированный список операций кэшируется.
- Экран «Операции» разбит на карточки по дням и строится лениво.

Автотесты: `test/ledger_cache_test.dart` (7) — два движка с отдельными соединениями к одному файлу видят и сохраняют записи друг друга, запись в файле сразу после сохранения, перенос старого снапшота без потерь, повреждённая запись нового формата откладывается и удаляется с диска, мелкие правки не переписывают журнал, отсутствие лишних чтений без чужих записей, строго растущие метки времени. `test/large_ledger_ui_test.dart` (2) — 20 000 операций на экране «Операции» строят меньше 200 строк, поиск по всему журналу работает. Общий запуск: 133 теста PASS, также с `TZ=Europe/Moscow`.

Вручную на эмуляторе Android 15 (release x86_64): обновление поверх данных 4.1 перенесло журнал в формат по записям без потерь, новая операция пережила принудительную остановку процесса (`am force-stop`).

Ограничения: `flush` вызывается через реализацию Sembast (`SembastDatabase.flush`), его нет в публичном API. Если метод пропадёт, хранилище закроет базу, а это тоже дожидается записи. Замеры на телефоне не выполнялись. Sembast не вызывает `fsync`: при внезапном отключении питания могут пропасть последние секунды изменений. Это было и раньше; так пропала тестовая операция, когда эмулятор выключили через `adb emu kill` сразу после сохранения.

Найдено тестами и исправлено:
- На 320 px клавиатура PIN-кода выходила за край диалога на 12 px. Теперь она сжимается под доступную ширину.

Вручную на эмуляторе Android 15 (release x86_64), до двух этих правок:
- включение блокировки с PIN-кодом;
- экран блокировки после возврата из фона и после холодного запуска; пока приложение заблокировано, в дереве доступности нет сумм;
- неверный и верный PIN-код;
- скрытие в недавних приложениях: карточка «Баланса» пустая;
- вход по биометрии. Отпечаток добавлен в эмулятор, переключатель включается после системного запроса `BiometricPrompt`. «Заблокировать сейчас» сразу показывает запрос, касание отпечатка разблокирует.

Ограничения:
- iOS, macOS и Windows Hello не проверялись.
- На Android ниже 13 скрытие в недавних приложениях включает `FLAG_SECURE`, а он запрещает и снимки экрана.
- Снимки задач, сделанные до включения скрытия, Android показывает, пока задачу не закрыть.
- Забытый PIN-код восстановить нельзя: сбросить блокировку можно только очисткой данных приложения (это объясняет кнопка «Забыли PIN-код?»).
- Блокировка не шифрует журнал на диске.
