# ROADMAP — идеи развития BalanceFlutter

Список возможных функций для «Баланса». Это идеи, а не обязательства. Составлен
по состоянию версии 4.1.1 с опорой на то, что уже реализовано
(`FEATURE_PARITY.md`) и на известные пробелы (`FEATURE_PARITY.md`,
`VALIDATION.md`).

Идеи поделены на две группы. Первая затрагивает только этот клиент. Вторая
меняет модель данных или sync-протокол, а это общий контракт с BalanceServer,
BalanceWatch и нативными клиентами (`SYNC_PROTOCOL.md`, `docs/ecosystem/`), поэтому
такие изменения делаются только согласованно во всей экосистеме.

При реализации действуют правила из `AGENTS.md`: расчёты — в `FinanceMath`,
изменения данных — через `AppStore`, суммы — целые сотые, интервалы `[начало, конец)`,
корректировки не входят в аналитику и бюджеты.

## Приоритеты

1. **JSON-бэкап и восстановление.** Сделано в 4.2.0. Закрывает реальный пробел local-first
   приложения, не трогает контракт, объём небольшой.
2. **Уведомления о бюджете и прогноз трат.** Уведомления сделаны в 4.2.0,
   прогноз трат — в разделе «Аналитика».
3. **Счета и переводы.** Следующая большая функция всей экосистемы: сначала
   согласовать модель с BalanceServer, потом делать во всех клиентах.

## Только Flutter-клиент (контракт не меняется)

### Данные и надёжность

- [x] **Полная резервная копия и восстановление (JSON).** Экспорт в CSV
  теряет данные: нет UUID, знака корректировки, timestamps, своих категорий и
  бюджетов (см. `FEATURE_PARITY.md`, «CSV is lossy»). Без сервера сейчас нет
  способа перенести данные на другое устройство или восстановить их после сбоя.
  Восстановление должно проходить через `AppStore` и ставить изменения в
  очередь синхронизации.
- [x] **Восстановление при повреждённых записях.** Сейчас повреждённая
  локальная запись может сорвать инициализацию, а экран ошибки предлагает
  только повтор. Нужен карантин: отложить повреждённую запись в резервную
  копию и запуститься без неё.
- [x] **Диагностика при pull.** Повреждённая запись с сервера может
  блокировать страницу pull (курсор при этом сохраняется). Нужны понятное
  сообщение и способ пропустить или исправить такую запись.
- [x] **Импорт банковских выписок** (CSV/OFX Сбера, Т-Банка и других):
  сопоставление колонок, автокатегории по описанию, защита от дублей.

Сделано в 4.2.0: полный JSON-бэкап и восстановление по last-write-wins,
локальный карантин повреждённых записей, диагностика при pull (запись
пропускается и попадает в карантин, курсор сохраняется), импорт CSV (Т-Банк,
сопоставление колонок) и OFX с защитой от дублей. Контракт с сервером не менялся.

### Быстрый ввод

- [x] Кнопка «Повторить операцию» и локальные шаблоны частых трат.
- [x] Ярлыки в иконке приложения на Android/iOS («Расход», «Доход») и плитка
  Quick Settings на Android.
- [x] Виджеты на главный экран: общий баланс, траты за месяц, остаток бюджета
  (Android; виджет iOS — см. ниже).

Сделано в 4.2.0: «Повторить» и «Сохранить как шаблон» в меню операции, блок
«Быстрый ввод» на обзоре (шаблоны и до трёх частых трат за 90 дней), ярлыки в
иконке, плитка Quick Settings «Расход» и виджет Android с кнопкой «+».
Шаблоны — локальные настройки устройства и не синхронизируются.

- [ ] Виджет iOS (WidgetKit): нужно расширение и App Group в Xcode, собрать и
  проверить без Mac нельзя.

### Аналитика

- [ ] Сравнение с прошлым периодом («расходы на 12% выше, чем в сентябре»).
- [ ] Произвольный диапазон дат вдобавок к 1, 3 и 12 месяцам.
- [ ] Динамика по одной категории во времени.
- [ ] Прогноз трат до конца месяца по текущему темпу и предупреждение «бюджет
  закончится 22-го».
- [ ] Годовой отчёт.

### Список операций

- [x] Фильтры по диапазону дат, сумме и категории; сортировка по сумме.
- [x] Группировка по дням с итогом за день.

Сделано в 4.2.0: окно «Фильтры» с периодом (быстрые варианты и свой
диапазон `[начало, конец)`), суммой «от — до» и категориями; активные фильтры
— удаляемые чипы и счётчик; сортировка по дате и по сумме; строка «Найдено» с
суммами расходов и доходов. Дни — отдельные карточки с итогом дохода и расхода
(без корректировок, как в аналитике). Логика — `lib/domain/transaction_filter.dart`.

### Уведомления

- [x] Локальные уведомления при 80% и 100% бюджета (пороги уже используются в UI).
- [x] Ежедневное напоминание внести траты.

Сделано в 4.2.0: предупреждения о бюджете текущего месяца при 80% и 100%,
по одному на порог, в том числе после фоновой синхронизации на Android. В
тексте только проценты, без сумм. Ежедневное напоминание в выбранное время
(Android, iOS, macOS) переносится на завтра, если сегодня уже есть операции.
Нажатие открывает бюджеты или новую операцию. Всё выключено по умолчанию;
разрешение спрашивается при включении.

### Приватность

- [x] Блокировка PIN-кодом или биометрией.
- [x] Скрытие сумм в списке недавних приложений.

Сделано в 4.2.0: PIN-код из 4–8 цифр хранится только как хеш PBKDF2 в
защищённом хранилище; вход по отпечатку или лицу (Android, iOS, macOS,
Windows Hello); блокировка при запуске и через выбранное время в фоне;
нарастающая задержка после 5 неверных попыток. В переключателе приложений
вместо сумм — заставка, на Android 13+ через `setRecentsScreenshotEnabled`.
Блокировка скрывает интерфейс, но не шифрует данные на диске.

### Десктоп

- [x] Горячие клавиши: новая операция, поиск.
- [x] Блокировка от запуска второго экземпляра. Сейчас межпроцессная
  блокировка есть только на Android и Web (`FEATURE_PARITY.md`, «Desktop
  multiple independent app processes are not coordinated»).

Сделано в 4.2.0: Ctrl/⌘+N — новая операция, Ctrl/⌘+F — поиск, Ctrl/⌘+1…5 —
разделы, Ctrl/⌘+L — заблокировать; список в настройках. Повторный запуск
поднимает уже открытое окно (Linux — `GApplication` через D-Bus, Windows —
мьютекс, macOS — система). На случай двух процессов `RuntimeLock` на десктопе
держит файловую блокировку ОС на каждую операцию, как на Android.

### Производительность

- [x] Измерить и оптимизировать работу на большом журнале: сейчас снапшот
  scope целиком загружается в память и переписывается на каждое изменение.

Сделано в 4.2.0: журнал хранится в Sembast по записям и пишется только
изменёнными записями одной транзакцией; база остаётся открытой, а данные не
перечитываются, пока не сменилась общая ревизия `ledgerRevision`; список
операций строится лениво по дням. Изменение при 50 000 операций — около 20 мс
вместо 2,8 с. Замеры — `VALIDATION.md`, бенчмарк — `tool/benchmark/`.

## Требует изменения контракта во всей экосистеме

Каждый пункт — это изменение модели данных и `/v1` API в BalanceServer,
`SYNC_PROTOCOL.md` и всех клиентов, включая BalanceWatch.

- [ ] **Счета и переводы:** наличные, карта, вклад. Перевод между счетами — не
  доход и не расход. Сейчас баланс один на всё.
- [ ] **Регулярные операции и подписки** (аренда, связь, сервисы) с
  автосозданием или напоминанием.
- [ ] **Мультивалютность:** валюта на уровне операции и конвертация по курсу.
  Сейчас валюта влияет только на отображение.
- [ ] **Цели накоплений** с прогрессом.
- [ ] **Теги** в дополнение к категориям.
- [ ] **Фото чеков** (вложения к операциям).
- [ ] **Общий семейный бюджет:** несколько пользователей на одном наборе данных.
- [ ] **Долги и займы:** «я должен» и «мне должны».
